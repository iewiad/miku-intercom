# 首次启动与设备初始化

依赖 Python 3、仓库要求的 Go；启用板端入口还需系统 `openssl`。在仓库根目录运行：

```sh
python3 tools/dev.py
```

等待 `Service ready` 后打开 <http://127.0.0.1:18792/>。同机双端演示时，第二个窗口打开 <http://localhost:18792/>，两个地址各自保存独立身份；也可使用独立浏览器配置或普通窗口加无痕窗口。两个普通窗口若都使用同一地址，会共用身份并触发标签接管，不能作为两名成员。保持两个窗口可见，一端建群、另一端输入口令加入，再分别启用群音频。麦克风只在页面明确操作后开启。按 Ctrl-C 结束本次服务。

工具默认只监听回环地址。构建产物、服务数据和日志保存在忽略目录 `work/local-dev`；目录为 0700、配置和密钥为 0600。再次运行会重用原身份和群数据，不清空旧数据、处理旧锁或结束其他服务。端口占用时直接报错。

## 启用同一局域网内的板端

板子需预先烧录本仓库群语音固件，构建和应用分区升级见[固件说明](../firmware/esp32-s31-rti/README.md)。首次没有保存 Wi-Fi 时，在板子触屏上选择网络并输入密码；成功连接后进入群语音页。

把示例 IP 换为这台电脑当前已分配的 RFC1918 IPv4。工具不会自动选择网卡。

```sh
python3 tools/dev.py --lan-ip 192.168.31.149
```

浏览器仍使用回环地址；板端入口为指定 IP 的 HTTPS 18793，媒体 UDP 范围默认为 40000–40199，可用 `--device-port`、`--udp-min`、`--udp-max` 调整。电脑与板子须能在测试局域网内互通。

首次启动创建 7 天有效的 ECDSA 开发 CA 与带该 IP SAN 的服务证书；不安装系统根 CA、不上传任何文件。再次启动验证证书期限、IP 和密钥。证书过期或 IP 改变会拒绝启动，不覆盖旧 CA 或凭据；可保留旧目录，用 `--work-dir work/local-dev-new` 建立独立环境，再明确初始化板子。新目录有独立的身份和群数据。

## 明确写入 USB

只有加上 `--provision-board` 才访问 USB、写入 NVS、重启板子并同步 UTC 时间。它只创建或重用设备身份，不创建群；板子启动后可在界面输入入群口令。

```sh
python3 tools/dev.py --lan-ip 192.168.31.149 \
  --provision-board --serial-port /dev/cu.usbserial-210
```

USB 辅助工具需要 `pyserial`。如果系统 Python 没有它，用 `--board-python /绝对路径/到已有环境/bin/python` 指定已有解释器。设备配置保存在该工作目录的 `board-config.json`，重试会校验并重用；不要把它或服务快照提交到仓库，也不要把凭据贴进聊天。

固件在 Wi-Fi 取得 IP 后自动通过 SNTP 校时。若当前网络无法访问时间服务器，服务已运行时可在另一个终端通过 USB 同步 UTC（无须重写配置或重启）：

```sh
python3 firmware/esp32-s31-rti/tools/intercom_config.py \
  --port /dev/cu.usbserial-210 --sync-time
```

## 可选浏览器语音指令

已有私有 RTA 配置时，附加 `--voice-config /绝对路径/voice-config.json`。工具只检查该文件为本人所有的私有普通文件，并把路径交给服务；不会显示内容，也不会在启动时调用 RTA。配置格式与权限按[开发指南](development.md)中 RTA 配置章节准备。板端 RTA 凭据继续使用原设备 NVS，USB 群配置不改写它。

已有本机触屏入群、口述切群、六方向完整语句听测和音量软重启保持证据。新环境仍需复验实际链路；完整演示、隔离的听测方法与结束后的关闭检查见[演示与收尾指南](demo.md)，具体已通过范围见[验收记录](acceptance.md)。
