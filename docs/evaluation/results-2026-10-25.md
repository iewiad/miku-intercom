## 输入、冻结与评分

原 60 条需求在首次模型调用前由 `5b6c0cd` 冻结，38 条推荐、22 条拒答，四例要求覆盖全部明示职责。原集随后用于提示改进与回归，最终成绩不是独立测试成绩。新增 H01–H24 在 `09f4d01` 冻结，14 条推荐、10 条拒答，两例要求完整覆盖；仅在 v3 选定后调用一次，此后未据结果改提示。

两组均使用五种合成目录。作者与第二个 agent 先分别判断需求/职责，再比较标注；没有修改冻结标签迎合模型输出。这不是两位人类独立标注。保留集作者看过原集标签、基线前 30 条理由和前 37 条通过的进度，审阅者也有原基准设计先验；暴露范围详见[评估协议](README.md)及两份 label-review。新需求没有逐字重复，但与原目录相关，不能假定独立同分布。

模型只见 need 和已授权候选，不见 case ID、分类、正确集合或评审 notes。每例走新的内存控制服务、真实 HTTP handler、生产适配器与严格解析，始终不确认、不切群，不建立群媒体。实际候选顺序记录为合成 key；随机 ID 排序导致位置不固定，模型采样也未控制，不能把版本差异全部归因于提示。

格式/传输/清理失败独立计数，不能记为成功拒答。策略成功要求结果有效：负例为空建议；正例非空、所有建议都在允许集合，明确多职责还须完整覆盖。可替代的合理群不要求全选。precision 以实际建议为分母，其余主要成功率保留全部计划例分母；误推荐率同时保留全部计划负例和有效负例口径。本轮全部有效，两种负例口径一致。理由忠实度独立于 key 评分，空建议不进入理由分母。

改进只增加通用职责约束：区分事项与操控、信息不足则拒答、各建议分别覆盖明示事项、不凭潜在成因或上下游关系增加群。没有按 case 或部门硬编码，也没有关键词、Mock 或固定建议兜底。严格权限和确认契约保持原逻辑。

## 理由仍需优化

独立 agent 逐建议核对需求、候选职责与实际理由，基线 44/48 有依据，v3 原集 43/46，v3 保留集 17/17。v2 没有完整理由审阅，不给整批分数。各批均未发现无依据在线/接听承诺或已执行声明；不由此推断以后也不会出现。

v3 原集的三个问题仍保留：C16 把“桌子旁边湿了”扩成“桌子被浸湿”；C22 增加“有线/无线均无法上网”；C25-device 把排查投影故障职责扩成明确覆盖维修。选组可以正确，理由仍可能添写事实。Issue #20 跟进事实/职责范围标注、人类审阅及受证据约束表述。保留集本次全部有依据，不抵消原集已见缺陷。
