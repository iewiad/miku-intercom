## S1 无板软件验证

首切片 [PR #5](https://github.com/iewiad/miku-intercom/pull/5)，原实现提交 `b56cbfd`；PR #5 已合并至 main（de0f864），可直接按开发指南运行。使用 Go 1.27.1、Node.js 26.3.1 / 24.19.0 验证；模块最低 Go 1.24，浏览器测试要求 Node 22+。从 `server/` 运行 `go test -race ./...`、`go vet ./...`、`node --test internal/httpapi/web/*.test.js` 均通过。

另以临时服务和合成身份走真实 HTTP：建群、错口令/重复入群、第二群不打断、跨群拒绝、切群操作重放、抢麦冲突/忙后重试、先释放后到达、旧释放不清新租约、切群释放；重启后成员和终态保留、麦权清空、旧启动代次拒绝，快照权限 0600。Chrome 使用 127.0.0.1 与 localhost 两个独立存储验证页面流程、同身份标签接管及 320px 窄屏；更换合成数据后，401 提示与按钮重建身份通过，无需 DevTools；无音频权限请求。临时数据与日志不进入 Git。

这些证据只覆盖控制状态；浏览器群媒体、板端群音频、语音切群和需求推荐不能据此标记通过。本轮没有连接板子、读取 RTA Key 或调用原网关。

禁止将旧工程 README / 历史日志中的通过记录当作本项目的证据。

原凭据故障发生在鉴权阶段，未据此判断模型或音色不可用，也未更改其授权。现已换用用户批准的凭据中心 Key，原模型在新 Key 的 Profile 列表中可见；宿主验证使用同一原网关，旧路径继续兼容。

新 Key 只保存在板端 NVS 和本任务受限的忽略临时目录（文件权限 0600），没有写入源码、聊天或原始串口日志；跟踪文件的精确匹配检查为 0。宿主同模型创建请求为 201，字段形状确认 Token 为 860 字节，诊断会话提交 Stop 返回 202。实际源码提取的合成数据解析回归 10/10、创建失败清理回归 5/5，ASan / UBSan 无错误；不替代真实网络和音频验收。

修复后板端真实建会话、语音回复、最终转写和本次会话停止已通过，未见 API/transport error 或 panic。停止后的第一次服务端读取尚为 provider_connected，随后复查已为 ended 且包含结束时间；不将异步停止窗口误判为已即时结束。

旧固件解析失败时丢失的 Session ID 无法通过客户接口枚举，先前这些会话是否回收尚未确认；服务端有到期释放机制，但本次成功会话的 ended 不能代替那些会话的逐条清理证据。群服务、板↔浏览器群音频和切群仍按各自未完成项推进。
