# 声路同行：实机视频导读与证据边界

## 可复制的项目简介

声路同行（Miku Intercom）面向临时小组协作，提供浏览器与 ESP32-S31 板端的按住对讲、群名语音切换和按需求找组。我们实现独立 Go 控制与媒体服务、成员权限、麦权租约、PTT 门控、版本化切群、幂等持久操作及两端恢复。普通群音频由对讲服务转发；RTA 复用实时转写与文本模型能力，未训练新模型。主动指令只在已授权群内产生候选，选卡不执行，需单独确认并由服务端复验权限、版本、目录和期限。S5 按协作事项推荐，填写职责与固定中性说明分开展示，不承诺在线或已接听。本片是一块板与 Chrome A 的局域网实拍，展示核对、确认、恢复和目标群对讲。主片标明手机续拍，S5 使用连续第三段手机素材；音轨同步用于剪辑，不是延迟测量。额外测试和失败记录另列，不作零错误或 ASR 准确率承诺。

## 实现范围与 RTA 分工

我们实现的应用层包括独立 Go 对讲服务、群与成员权限、当前群版本、麦权租约、PTT 收发门控、WebRTC/Opus 群媒体转发，以及 Chrome 和 ESP32-S31 触控客户端。切群使用持久、幂等的操作记录；客户端在结果未知时继续核对原操作，取得终态与最新权威状态后才恢复群媒体，恢复时保持未按麦。

普通对讲的音频在终端和独立对讲服务之间转发，不进入 RTA 转写或推荐模型。用户明确开启语音指令或需求采集后，才复用现有 RTA 的实时转写；已知转写会话清理完成后，应用再处理本次授权目录中的候选。群名目标唯一精确命中可省去文本模型，通过否定等门禁的其他自然表达、轻微错字或同音候选交给受限的 `voice-target-v2`；S5 使用独立的 `direct-duty-v3`，按主动描述的协作事项匹配群职责。本视频的“帮我转到设备排障演示群吧”实例记录为 `source=model`、1 个候选，不据此推整体命中率。

模型只有建议权。候选到达、选卡、取消或到期不会自动切群，用户必须单独点击“确认进入”。服务端在确认事务中重新检查身份与权限、当前群版本、完整授权目录摘要、服务 epoch 和有效期，并原子保存建议消费与幂等操作终态；模型不能代替这些控制契约。代码细节见 [009 需求推荐](specs/009-model-recommendation.md)与 [010 语音目标核对](specs/010-voice-target-review.md)。本片没有逐项演示所有异常分支。

S5 卡片中的“群职责（填写内容）”来自建群时填写的目录内容，并非服务端核验过的真实能力。“推荐说明”是固定中性文案：“模型建议联系该组，请核对群职责后确认。”，不是模型自由推理过程，也不表示成员在线、空闲或已接听。片中演示群分别负责设备排障与物资协调，使用明确标记的示例职责。

## 声音、可读性与保留的原貌

PTT 段使用实际 Chrome A 接收音轨；主动口述指令与需求段使用手机现场录音。A 自己说话不会天然出现在 A 的接收音轨中，因此不能把现场口述与电子回传混为同一条证据。手机与电脑音轨经过分段同步以便剪辑，不用于计算端到端延迟、声学停发时间或长期时钟漂移。

原片中，部分首页辅助行可能残留先前的“正在确认推荐切群结果，确认前暂停音频”文案，即使右上状态已就绪。成片保留这一原貌；应分别核对权威当前群、就绪指示和之后的 PTT，不用该旧辅助行单独判断恢复结果。手指遮挡和少量屏幕重影也保留，没有替换成合成产品画面。

最终文件为 H.264/AAC、1920×1080、30fps、SDR BT.709。完整音视频解码、颜色标记及字幕交界检查通过；关键画面和修正后的字幕边界做过实际抽帧复核。这些技术检查不是逐帧人工观看或成片真人听感评分。
