## 必交范围

- 浏览器建群、分享口令；板端输入八位口令加入，已加入群可手选或语音选择。
- 同群半双工 PTT，只有后台麦权有效且媒体就绪时发送。恢复始终未按麦。
- 一块板加两个浏览器完成可运行演示。数值传输、真实 RTA 转写和人工听测分别留证。
- 首次 Wi-Fi 配网、保存后连接、联网校时、私有 LAN/TLS 启动与 USB 初始化有明确入口。

## 板端口令入群

口令字母表为 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，共八位，接受小写并归一为大写。界面打开输入框即取消发言；键盘仅暂存本次输入，确认成功排队或关闭时清空，不打印或录制。回调只校验、复制有界输入并排队，不执行网络、NVS 或媒体创建/销毁；控制 HTTP、日志和媒体生命周期由单一 worker 执行，界面通过受控发布更新。

已知空群状态可以入群，不要求先有群 Peer。设备服务配置的 `group_code` 改为可选，仅保留旧 USB 自动加入的兼容用途；身份、Token、CA 与服务地址仍必须配置。每次成功加载配置的连接会话最多自动尝试一次旧口令，失败后保留键盘纠正入口，避免循环错误尝试耗尽身份限流。首个群由服务端自动进入；追加成员资格不主动切换当前群。入群失败或响应不明时刷新权威状态后再恢复媒体，避免使用可能已经变化的旧绑定。

## 主动语音指令

板端和浏览器都提供显式语音入口。共同前段为：取消 PTT、退休群 Peer → 原 RTA 命令会话 → `session.updated` 与采集准备完成 → 当前代次首次最终用户转写 → 停采集 → 后台只读解析。执行与清理顺序按客户端区分：

- **板端**：关闭命令 Peer → 已知 RTA 会话 stop 并查询到远端终态 → 持久化原有切群操作并确认终态 → 核实最新状态 → 重建群 Peer。
- **浏览器**：先持久保存原有切群请求并提交/查询终态，期间保留命令 Peer 但采集已禁用 → 关闭命令 Peer 并查询确认 RTA 远端终态 → 按最新控制状态或仍待确认的原操作决定恢复。隐藏页面或中断时可以提前执行 RTA 清理，已提交的切群请求仍独立确认，不会被撤回。

两端都把“命令 Peer 已关闭且已知会话查询到远端终态”和“当前群状态已确认、无待确认切群”作为新建群 Peer 的前提。`POST stop` 返回 `202` 仅表示受理；继续向原网关查询同一个会话，只有匹配 ID 的 `ended`、`failed` 或 `expired` 才解除清理等待。查询失败或仍为活动状态时重试，不以请求受理代替结束。

实际原网关已出现终态后查询回退的观测，见[验收记录](../acceptance.md#首版实际链路与平台边界)。本地终态查询是恢复门槛，不构成平台跨实例一致性或稳定资源回收的证明；平台问题需独立修复。

RTA 命令会话在创建请求中设置 `enable_search=false`；后续 `session.update` 不携带该字段。真实静音 Pion A/B 已确认，当前网关会拒绝含此字段的更新并返回 `rtid.error / invalid_session_update`，省略后可取得 `session.updated`。两端把 `rtid.error` 作为终态错误立即停采集，避免等待配置超时。

指令阶段暂时无法收听群聊。命令模式不发欢迎请求、关闭自动回复、禁止播放模型音频，不常开监听。板端转写限 512 UTF-8 字节，浏览器及后台解析限 256 个 Unicode 字符；助手文字、增量、旧代次及重复最终事件均不能执行。全文不进入日志或持久数据。

`POST /api/v1/voice/resolve` 使用既有身份鉴权，请求 `{transcript}`，只读返回 `{group_id,name}`。仅接受完整“切到/切换到/进入 + 已加入群名”命令；未知、歧义或普通聊天返回明确拒绝。解析不改变当前群，执行仍由原有 `operation_id + group_id + expected_version`、权限校验与终态查询负责。

提交前可取消；提交后等待原操作终态。取消立即关闭采集/媒体准入，进行中的有界 HTTP 需由 worker 完成后清理。已知 RTA 会话 stop 未确认时不恢复群 Peer、不另建 RTA。板端切群已提交后的停止/软重启继续复用 005 日志；请求未提交的临时语音意图不跨重启重放。

板端界面命令状态带单调 revision，接受、阶段变化和终态均推进。旧 idle 发布不能提前解锁本地等待；极速完成也能解锁。浏览器以当前会话对象和 generation 排除迟到结果。两端命令期间 PTT、手动切群和重复入口均被门控。

板端沿用原 RTA 直连创建接口：若创建响应不明且无法取得 `session_id`，本地没有建立命令 Peer、没有开始该会话的音频采集，也不会执行切群；清理本地意图后可恢复群音频。此恢复不证明未知远端会话已经结束，远端回收需依赖平台到期机制或服务侧另查，不能记为 stop 确认通过。浏览器代理的持久 `command_id` 恢复另按下节契约处理。

## 浏览器 RTA 配置

服务端默认不开启 RTA；通过显式私有配置开启本地信令代理。长期 API Key、RTA 短期 Token 和 RTC endpoint 由服务端保管，浏览器仅提交 offer、取得 answer 并使用 DataChannel。会话绑定设备身份与 command_id；创建或停止结果不明不以新 ID 盲重试。配置只允许显式 HTTPS origin，或精确指定的数字节点域名后缀与端口，拒绝跳转及不匹配路径；群音频沿用独立 Go 转发链路。

## 验证与交付

自动回归覆盖：空群入群、错误/限流与丢响应、命令忙与迟到授权、首次 final、旧代次/取消、RTA 创建/停止失败、提交前后边界、相同操作精确重放、UI 旧 revision、恢复未按麦和群隔离。主机 doubles 不代表真实 RTA、RTOS、I2S 或 Flash 断电验证。

实际运行分别记录：完整 IDF 构建、应用分区升级及独立校验、浏览器真实 WebRTC、板端入群/取消/恢复、真实 RTA 信令与最终转写、单 Peer 资源清理。触屏入群、两轮口述切群、取消恢复和六方向完整语句听测已有分项证据，浏览器 A/B 最后关闭报告也已补齐；这些不能据此推断完整演示已串联通过。剩余人工工作为完整现场演示、回声与延迟专项观察及新增诊断进度界面确认；操作见[演示指南](../demo.md)，实际范围以[验收记录](../acceptance.md)为准。物理断电、第二块板及局域网外场景另列验证范围。
