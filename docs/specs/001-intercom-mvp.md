# 声路同行：最小对讲闭环执行规格

状态：首版执行规格，2026-10-23。负责人：戴伟。采用轻量规格驱动，当前从无板控制面开始开发；完成状态只在验收记录维护。

产品目的与体验以 [product.md](../product.md) 为准，技术职责与路线见 [architecture.md](../architecture.md)，实际通过证据仅记入 [acceptance.md](../acceptance.md)。本稿负责功能编号、跨组件约束、待定契约与执行顺序；不再维护另一套完成状态。

## 用户故事与优先级

| 编号 | 范围 | 用户故事 | 必须观察到的验收结果 |
| --- | --- | --- | --- |
| U1 | 基础必交 | 发起人建群，成员凭口令加入 | 错口令不加入；后台确认后可进入第一个群；加入第二个群不意外打断当前群 |
| U2 | 基础必交 | 成员按住向当前群发言 | 获权后才传输；一群一人发言；板与浏览器真实双向声音；同群其余成员听见，非当前群听不见 |
| U3 | 基础必交 | 成员说出群名切换 | 明确触发；仅处理本次指令的最终用户转写；后台确认目标且音频恢复后才能显示成功 |
| U4 | 基础必交 | 异常后恢复沟通 | 松手/取消/断线停发；失联不占麦；切群结果不明时确认请求终态再恢复；恢复后未按麦 |
| U5 | 增强，待验证 | 成员描述需求，找到对应小组 | 只推荐已加入且有权限的群；显示职责及理由；用户确认前不切；确认时重验权限并复用 U3/U4 |

U1–U4 构成必交闭环。U5 已纳入产品规划，不能替代 U3，也不能作为基础闭环验收的前置条件。示例“设备坏了，找个能维修的人”只对应职责合适的小组，不保证某个个体已接听。

## 跨组件规则

- 群、成员资格、当前群、发言权与切群请求终态由独立对讲服务决定；设备显示或模型回复不能替代后台状态。
- 发起人与成员是通用产品角色，不新增车队、企业组织或行业任务等实体层级。
- 普通群音频直接转发，不进入模型；模型仅参与用户明确触发的语音命令/需求推荐。
- 任意时刻只有一个当前群。服务端和客户端都需限制未经发言权授权的音频；切群清理旧播放队列。
- 首版单 Peer 串行复用旧音频与 RTA 路线待真机验证。回调只投递带代次的事件，生命周期 worker 执行释放和重连，不在接收任务中关闭自身。
- 请求提交前允许取消；提交后进入确认流程。查询必须确认该请求已终结或不再可能生效，再根据权威当前群恢复。
- 所有恢复都回到未按麦状态。后台已切成功但 RTC 失败时，显示目标群连接失败，不能误报原群或可对讲。
- U5 的职责简介和模型输出只作为参考数据；只允许候选群集合内的目标，无法验证输出时不执行。选中的推荐必须明确确认，并在执行时重新鉴权。
- 不预设实际 RTA Profile 支持 tools、结构化输出或可靠置信度；不为了 U5 新增未经验证的 Provider/PCM/WSS 链路。

## 按切片冻结契约

首切片的身份、持久化、手动切群与麦权 API 已定义于 [002-control-api.md](002-control-api.md)。下表区分当前范围和后续需要补齐的接口；本文保留跨组件约束，不复制字段。

| 契约 | 需要明确的内容 | 验证重点 |
| --- | --- | --- |
| 身份/入群，S1 | 002 已定义随机终端凭据、8 位口令、首次进入、快照持久化 | 不能凭昵称或群名越权；重启重连仍核验有效状态 |
| PTT 控制，S1 | 002 已定义 3 秒租约、1 秒续租、启动代次、申请期限与取消；媒体另验 | 同时抢麦、松手先于 ACK、迟到获权、掉线释放、不自动排队 |
| RTC，S2/S3 | 待补 SDP/ICE/Opus、连接鉴权、服务端媒体门控、队列上限和清理 | 板↔浏览器实音频、群隔离、慢接收端和重新连接 |
| 切群，S1/S4 | 002 已定义手动操作幂等/版本/终态；S4 补语音指令代次和 Peer 生命周期 | 不误切、不重复、无结果不猜测、确认前不能误报成功 |
| 需求推荐 U5 | 可选群职责、候选集及版本、推荐有效期与单次消费、用户确认、输出校验 | 未授权群不能成为目标；过期/撤权/重复确认/含糊输出不误切 |

## 最小验证用例

| 编号 | 触发 | 预期与证据 |
| --- | --- | --- |
| A1 | 错误口令、正确口令、加入第二群 | 后台成员与当前群符合 U1；不能以页面提示代替后台确认 |
| A2 | 板与两个浏览器对讲，同时申请发言 | 实听双向与一对多声音；一次仅一个有效发言权，其他群收不到 |
| A3 | 按下后很快松手，之后才收到获权 | 不开麦或立即释放，不出现迟到的自动发音 |
| A4 | “切到后勤组”，以及不存在/无权限的群 | 有权目标确认并恢复后可对讲；其他情况当前群不变且可恢复 |
| A5 | 切群请求超时、查询后迟到响应 | 确认同一请求终态再恢复；不把旧请求结果应用到新指令 |
| A6 | 目标群已切成功，RTC 连接失败 | 目标群连接失败并重试，未显示成功或误报回原群 |
| A7 | 断网、进程重启、重复/迟到转写 | 不持续发音或占麦；后台核实后恢复，未按麦 |
| A8 | 连续十次切群与资源观察 | 无崩溃、持续资源下降、旧音频混入或残留占麦；记录两个阶段真实耗时 |
| A9 | U5：需求推荐、未确认、含糊、过期、权限变化 | 候选内推荐；未确认无动作；确认时重验权限；失败恢复并可用明确群名切换 |

A1/A3/A5 等适合协议与状态测试；A2/A4/A6/A8 仍需真机与实音频证据。交互草图检查、旧 README 或历史日志均不能替代本项目验收。

## 执行顺序

| 切片 | 开发内容 | 验证门槛 |
| --- | --- | --- |
| S1 无板控制面 | Go 服务、同源浏览器、身份/建群/入群/当前群/麦权 | 002 的 HTTP、并发、迟到请求、持久化、重启测试；两独立身份操作 |
| S2 无板群音频 | 先补媒体契约，再做浏览器 WebRTC 与服务端门控 | 两浏览器双向、第三接收端一对多、跨群隔离、断线/释放；不能仅看按钮 |
| S3 板端 | 用户安排接板后接入群控制与媒体 | A2/A3/A7，板↔浏览器实音频、权限与触摸取消 |
| S4 语音切群 | 原 RTA 最终转写接入同一切群接口，串行 Peer 恢复 | A4/A5/A6/A8；实际媒体恢复与资源观察 |
| S5 增强 | 授权候选群、需求推荐、用户确认 | 先补契约，再按 A9 验证真实模型；不阻塞基础交付 |

S1 的状态测试可覆盖 A1/A3/A5/A7 的控制部分，不能勾选完整的群实音频或语音切群验收。当前无需连接板子、查询原 RTA 或读取开发凭据。各切片通过后，证据与限制写入 [acceptance.md](../acceptance.md)。
