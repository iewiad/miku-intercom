# 一板两浏览器：演示与收尾

面向临时小组协作，用“全员群”和“后勤组”展示同一套通用产品。预计约三分钟，准备和异常处理不计入时长。已有分项证据见[验收记录](acceptance.md)；本指南是可重复操作的脚本，不能作为整场演示或录像已完成的证据。

## 开始前

1. 先按[首次运行指南](first-run.md)准备服务、指定 LAN IP 的 TLS 入口和板端配置。已有运行中的服务应继续沿用其数据、身份与 CA；不要为演示重建环境或重写板端配置。新环境才使用指南中的初始化步骤。
2. 板端 Wi-Fi、时钟和开发证书须有效；需要语音切群时，板端必须已有可用 RTA 配置。浏览器语音入口还需服务端显式配置 RTA。只演示群对讲不需要调用 RTA。
3. 两个可见浏览器窗口分别用 `http://127.0.0.1:18792/` 与 `http://localhost:18792/`，或独立浏览器配置。相同来源的普通窗口共享身份，不能充当两名成员。窗口并排，避免隐藏页面关闭媒体。
4. 三个终端使用不同身份。为可重复演示，可在准备时创建带当次后缀的两个唯一群名，并事先让所有终端加入；现场重演入群时，只让尚未加入的端输入现场生成的口令。追加群只增加成员资格，仍需主动切换。下文“全员群”“后勤组”均指本次实际完整群名；带后缀时，语音也必须说全名。
5. 同一电脑只打开一个浏览器的收听输出，另一端静音；耳机输出先单独确认。板端用适中音量，靠近麦克风正常说话。下文涉及播放、开麦和语音指令的步骤应有人在场时明确操作。

成员数是已加入总数，包含离线成员；不能解说为“在线三人”。PTT 可用、当前群正确和媒体就绪分别确认。若播放受阻，普通页面点“点击开始收听”，诊断页点“开始收听 / 重试播放”。

## 产品演示脚本

| 时间 | 操作 | 通过判据 |
| --- | --- | --- |
| 0:00–0:30 | A 创建全员群并分享口令；B 输入口令加入。板端先点“连接群语音”，目录同步后点“加入群组”输入口令。已有身份的端显式切到本次全员群，三端启用并连接群音频 | 初次入群会自动进入；已有当前群的端需主动切换。浏览器显示三名已加入成员；三端当前群正确、媒体就绪、未按麦 |
| 0:30–1:20 | A 按住发一句话、松手；板端按住回复；B 再发一句。另做一次短暂同时抢麦 | 每个方向听到完整语句；松手停发；同时申请仅一方获权，另一方不能发送，且不会排队自动开麦 |
| 1:20–2:10 | 事先加入后勤组的 B 手动进入；板端点“语音切群”→“开始语音”，等允许说群名后说“切到”加本次后勤组完整名称。确认结束弹窗的权威当前群，再返回对讲；板端与 B 互相回复，A 留在全员群 | 群音频恢复且保持未按麦后才能对讲；B 听到板端，A 在另一群听不到新群语音 |
| 2:10–3:00 | 另开一次语音指令，说“切到”加一个不存在的群名；结束后检查仍为后勤组，再手动返回全员群 | 未提交无效切换，原群可恢复；返回全员群后仍未按麦；解说普通对讲由独立服务转发，模型只参与主动指令 |

语音会话结束曾实际等待约 16 秒，三分钟只是目标节奏。结果未知时应等待原操作确认，不通过刷新、换操作号或反复点“开始”缩短等待。只有明确目标已确认且群音频恢复，才能解说为可对讲。必要时暂停计时处理，不省略失败状态。

在一台电脑上分别证明某个接收方向时，先静音其他播放端，避免把电脑外放刺激或板端声音误当成耳机返回。完整六方向复验可依下表逐项运行，每次只启用一个发送端：

| 发送端 | 接收端 | 其他播放端 |
| --- | --- | --- |
| A | B 耳机 | 板端音频停止，A 收听静音 |
| B | A 耳机 | 板端音频停止，B 收听静音 |
| A、B 分别发送 | 板端扬声器 | 两浏览器收听静音 |
| 板端真人近讲 | A、B 分别戴耳机收听 | 非目标浏览器静音；不播放电脑外放测试音源 |

诊断页可使用[开发指南](development.md#无板音频诊断)中的固定合成 WAV 替代浏览器真人音源。仅在前台点击发送，等待完成再切窗口；失焦会正常取消本次发言。诊断音、RTP 包数、PCM 数值与人工听清分别记录，不能互相替代。此诊断步骤不等同普通产品页的触控流程。

## 需要单独记录的观察

- 新环境和新镜像各记录实际提交、固件 SHA-256、测试拓扑、音源、接收端及听测结果；不要把历史版本结果沿用为新版通过。
- 完整脚本、浏览器新增进度提示、十次连续语音切群仍需独立观察；十次手动切群不等同十次 RTA 语音切换。
- 回声与延迟应另开专项：隔开物理音源，分别记录“触发到允许说指令”和“说完到群音频恢复”，以及普通对讲的测量方法。当前没有正式精确延迟或异地回声结论。
- 物理断电、第二块板、长时稳定性和局域网外可达性不在既有通过范围内。按需求推荐小组独立规划，不影响本脚本。

## 结束后

1. 先松手并取消尚未提交的指令；已经提交的切群等待同一操作终态，按权威状态恢复约定的当前群。不要清除待确认日志。
2. 板端点“停止连接”，确认未按麦；音量如需调整，拖动后松手保存。停止音频不等于把保存音量改为零。
3. 普通页面逐端点“关闭音频”；诊断页逐端点“停止并关闭全部测试音频”，在关闭页面前导出各自 JSON。
4. 核对诊断关闭报告中的采集已清除、开放 Peer 为 0、未持麦。报告只用于其实际页面与观察窗口，不能用一端报告代替两端。不要分享包含身份、Token、口令或原始声音的私有配置。
5. 恢复临时改动过的电脑声音输出与音量；所有端关闭后再决定是否停止服务。若继续开发则保留运行环境，不自动重建 CA、覆盖数据或处理其他进程的锁。

本次六方向听测结束时，板端已恢复“后勤组”、版本 21，音量 38% 且音频停止；浏览器 A/B 的最后关闭报告尚待导出。这是该次测试的收尾状态，之后运行仍以最新权威状态为准。
